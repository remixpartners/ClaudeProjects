# Remix Tuning Experiment — Training Set Spec

**Date:** 2026-07-18
**Context:** Justin asked what it would take to safely experiment with tuning Inkling (Thinking Machines' 975B open-weights MoE) for Remix use. Path chosen: Tinker (managed fine-tuning, per-token billing). Validate the recipe on a small model (Qwen3-8B, ~$20-40) before spending on Inkling (~$250-500 at current 50% discount).
**This doc:** what goes into the training set, in what format, what stays out, and how we know it worked.

---

## 1. Goal

One question the pilot must answer: **does tuning on our corpus make a model (a) sound like Remix and (b) know the Remix methodology well enough to be useful** — vs. just prompting a frontier model with the same material?

Non-goals for the pilot: replacing Claude for client work, serving clients directly, multimodal anything.

## 3. Format: instruction→response pairs, not raw dumps

SFT teaches behavior, not facts. Dumping the vault in raw teaches the model to *write vault notes*. Every training example is a JSONL pair: a realistic prompt (client question, drafting request, advisory situation) → the answer Remix would actually give. Four tracks:

### Track A — Methodology Q&A (~40% of pairs)
- Mine **real questions clients/leads have asked** (the `client-question-harvest` skill was built for exactly this — run it across Gmail + transcripts).
- Answer each from vault material: Stack × Scope, the Ladder, Kickstart/Pulse/EVE structure, Goldilocks Zone ICP, Guild vs Plantation, roadtrip-vs-cruise framing.
- Also synthesize Q&A from vault advisory/strategy notes where no real question exists yet (generated by Claude, grounded in and citing specific notes — this is methodology-internal use, not client deliverable).

### Track B — Voice & drafting (~30%)
- **Email:** sample Justin's actual sent mail; reconstruct the incoming context → his reply. Teaches greetings ("hey [name]-"), sign-offs ("-j"), "!!", ":)" , short paragraphs, B2B-capitalization exception.
- **Proposals:** transcript excerpt + client context → the proposal section actually shipped. The **partner-edit corpus is the highest-signal data we own** (draft → what Justin/Jason changed); use edited finals as targets.
- Voice guides become *system-prompt-style preambles* on these examples, not training targets themselves.

### Track C — Advisory moves (~25%)
- From transcripts: client statement/objection → how Justin or Jason actually responded. Captures the reframes, the pushback style, "what would have to be true," the pricing anchors ($40K Kickstart floor).
- Extraction is LLM work (per house rule: LLM over regex), one pass over the 205 transcripts.

### Track D — House rules as examples (~5%)
- Brand and format rules (no emdash in client-facing, chartreuse #E0F61F + ink #1D1D1C, numbered-options format, translatability) baked in as demonstrated behavior across the other tracks' examples, plus a small set of explicit correction pairs.

## 4. Exclusions (hard)

- **Personal:** Tough Pigeon, car wash, Lynda's app, Turnip, family sessions. Vault already has `EXPORT-EXCLUSIONS.txt` — honor it and extend it.
- **PII scrub:** strip client employee personal details, health info (MATTER-adjacent), anything from Partner Chats (Justin+Jason 1:1s stay out entirely — too raw).
- **Financial internals:** Mercury balances, comp targets, exit-landscape material. The model doesn't need it and it must never leak.
- **Client confidentiality decision (Justin's call before Inkling run, not needed for pilot):** if the tuned model stays *internal-only*, client engagement data is in-scope. If we ever offer a tuned model *to* clients, every other client's data comes out first. Recommend: pilot as internal-only, everything in except the exclusions above.

## 4b. PII scrub flow (runs locally — transcripts never leave our hardware)

Tooling: **OpenAI's gpt-oss open-weights models** (Apache 2.0, released Aug 2025; still OpenAI's current open family as of July 2026). Two members matter here:
- **gpt-oss-20b** — general reasoning model, ~14GB (MXFP4), runs on Kirby's Mac Mini via Ollama alongside the existing gemma4 stack. Does the actual redaction rewrites.
- **gpt-oss-safeguard-20b** — the safety-classifier variant: give it a written policy at inference time and it reasons over the text and labels violations, with visible chain-of-thought. Used as the *verifier*, not the rewriter (it classifies; it doesn't rewrite).

Pipeline (every transcript, before anything touches pair-generation):
1. **Redact (gpt-oss-20b, local):** rewrite each transcript against a written PII policy — personal names → stable pseudonyms/role tags ("[CEO-ClientA]", consistent within and across that client's files so dialogue still reads), strip emails/phones/addresses, health details, individual comp, kids/family mentions. Company names KEPT for internal-only training (revisit if model ever goes client-facing).
2. **Verify (gpt-oss-safeguard-20b, local):** second pass with the same policy classifies each scrubbed chunk pass/fail and flags residual PII; failures loop back to step 1.
3. **Spot-check:** Stafford reviews a random 10% sample + every flagged-then-fixed file; Justin sees a one-page summary of what categories were removed.
4. Scrubbed corpus is what Tracks A-C consume. Raw transcripts never upload to Tinker.

Why local matters: the entire point of scrubbing is that client-confidential text shouldn't transit a third-party API *before* it's clean. gpt-oss on the Mini keeps the dirty→clean step inside the tailnet at zero marginal cost.

## 5. Sizing & cost

- Target: **3,000-6,000 pairs**, avg ~1-2K tokens each → 5-10M tokens/epoch, 2-3 epochs.
- Qwen3-8B pilot: ~$10-30 train + a few $ eval.
- Inkling run: ~$150-500 at discounted $5.61/M train rate.
- The real cost is build effort: ~2-3 working sessions (question harvest, transcript extraction pass, email pairing, PII scrub, assembly), mostly automatable.

## 6. Eval (decide success before training)

- Hold out **50 real client questions** (never trained on) + 10 drafting tasks (emails, proposal sections).
- Blind three-way comparison: tuned model vs. base model vs. Claude-with-vault-in-context. Justin grades voice; grader rubric checks methodology accuracy against vault ground truth.
- Success bar for proceeding to Inkling: tuned small model clearly beats its own base on voice AND methodology; noticeably narrows the gap to Claude-with-context.

## 7. Build order

1. Stand up gpt-oss-20b + gpt-oss-safeguard-20b on the Mini (Ollama); write the PII policy; run the scrub flow over all 205 transcripts (§4b).
2. Run client-question-harvest → question corpus (exists as a skill; point it at scrubbed transcripts).
3. Transcript advisory-move extraction (one LLM pass over the scrubbed corpus).
4. Sent-mail sampling + context reconstruction (gws, ~500-1000 emails).
5. Partner-edit pairs from proposal-writer judge corpus (already structured).
6. Synthesize Track A/D fills, PII scrub pass, assemble JSONL, split train/eval.
7. Tinker pilot on Qwen3-8B → eval → go/no-go on Inkling.
